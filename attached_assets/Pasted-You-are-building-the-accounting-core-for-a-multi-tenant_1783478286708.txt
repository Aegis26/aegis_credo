HARD RULES (these are invariants — never violate them, and write tests that
prove each one holds):
1. Money is stored as integer minor units (cents) in bigint columns. Never use
   float, double, or JS number for monetary values. Do all math in integers.
2. Every posted journal entry must balance: sum of debit line amounts equals
   sum of credit line amounts. Reject any attempt to post an unbalanced entry.
3. Posted journal entries are immutable. Never UPDATE or DELETE a posted entry
   or its lines. Corrections are made only by posting a new reversing entry
   that references the original.
4. All lines of an entry commit atomically in a single DB transaction. If any
   line fails, the whole entry rolls back.
5. Account balances are always derived by summing journal lines. Do NOT store a
   mutable balance column as a source of truth.
6. Every table has an orgId column and every query is scoped by orgId. No query
   may read across tenants.
7. The ledger is append-only. Every write is recorded in an audit_log table
   (actor, action, entity, before/after, timestamp).
